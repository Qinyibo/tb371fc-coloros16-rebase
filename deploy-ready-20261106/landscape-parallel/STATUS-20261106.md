## Root cause (one shot)

Today's `pm disable-user` trim miscategorized **`com.oplus.pscanvas`** as AI/bloat.

| Package | Path | What it actually is |
|---------|------|---------------------|
| **com.oplus.pscanvas** | `/system_ext/app/OplusFlexibleWindowUI` | **Oplus Flexible Window UI** — settings + control for **平行视界** (`flexibletask.setting.SettingActivity`, FlexibleAppControlService, IndexSearchProvider) |
| **com.oplus.cosa** | `/my_stock/app/COSA` | COSA app-compat / enhance providers; Settings `key_com_oplus_cosa=1`; related to tablet app landscape / compatible mode UI |

With `pscanvas` disabled (`enabled=3`):
- Settings search entry for 平行视界 vanished (IndexSearchProvider offline)
- Flexible window per-app UI could not open
- Phone-style apps that depended on parallel/flexible layout appeared stuck in portrait / letterbox

`com.coloros.smartsidebar` and `com.oplus.multiapp` were **already enabled** and not the cause.
`com.coloros.floatassistant` remains disabled (悬浮助手 — not 平行视界); left off for minimal restore.

---

## Fix applied (minimal re-enable)

```bat
adb shell pm enable --user 0 com.oplus.pscanvas
adb shell pm enable --user 0 com.oplus.cosa
```

### Before
- Both in `pm list packages -d`
- pscanvas/cosa `enabled=3` (DISABLED_USER)

### After
- Both `enabled=1` (ENABLED), removed from disabled list
- `am start` (root) → `com.oplus.pscanvas/...SettingActivity` **Resumed / focused**
- Process: `com.oplus.pscanvas:FlexibleAppControlService`
- WM still has `FlexibleTaskController`
- Settings App landscape entry (`OplusSubSettings$AppLandscapeModeActivity`) opens
